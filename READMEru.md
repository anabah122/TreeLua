# TreeLua

Минималистичный 3D-движок для LÖVE 11.5. Это вся обвязка, которую three.js добавляет поверх рендерера — но без самого рендерера, ведь у LÖVE он уже есть.

Публичный API полностью срисован с [three.js](https://threejs.org/docs/), поэтому его документацию можно использовать как справочник. Пару намеренных отличий мы разобрали в разделе [Отличия от three.js](#отличия-от-threejs).

## Быстрый старт

```lua
local TL = require "TreeEngine"

local scene, camera, renderer, mixer

function love.load()
    local w, h = love.graphics.getDimensions()

    scene  = TL.Scene:new()
    scene:setBackground(0x171a21)

    camera = TL.PerspectiveCamera:new(60, w / h, 0.1, 1000)
    camera.position:set(0, 1.2, 3.5)

    renderer = TL.WebGLRenderer:new()

    local sun = TL.DirectionalLight:new(0xfff7eb, 1)
    sun.position:set(0.4, 1.0, 0.6)
    scene:add(sun)
    scene:add(TL.AmbientLight:new(0x474d5c, 1))

    local gltf = TL.GLTFLoader:new():load("assets/model/model3dtest.glb")
    scene:add(gltf.scene)

    mixer = TL.AnimationMixer:new(gltf.scene)
    mixer:clipAction(gltf.animations[1]):play()
end

function love.update(dt) mixer:update(dt) end
function love.draw()     renderer:render(scene, camera) end

```

Подключение библиотеки не засоряет глобальную область и не вешает свои хуки.

## API

### Математика

`Vector3` `Vector4` `Matrix4` `Quaternion` `Euler` `Color` `Box3` `Sphere`
`Plane` `Ray` `Frustum` `MathUtils`

### Ядро

`Object3D` `Group` `BufferGeometry` `Scene` `Raycaster`

Выбор объектов (picking) работает как в three.js, но с удобным дополнением. `setFromCamera` принимает нормализованные координаты экрана (NDC), а `setFromScreen` — это готовая обертка для обычных пикселей, которые вы получаете напрямую из `love.mousepressed`:

```lua
function love.mousepressed(x, y)
    local caster = TL.Raycaster:new():setFromScreen(x, y, camera)
    local hit = caster:intersectObjects(scene.children, true)[1]
    if hit then print(hit.object.name, hit.distance) end
end

```

### Геометрии

`BoxGeometry` `SphereGeometry` `PlaneGeometry` `CylinderGeometry` `ConeGeometry`
`TorusGeometry`

Базовые примитивы, чтобы собирать сцену без загрузки внешних файлов:

```lua
local mesh = TL.Mesh:new(
    TL.BoxGeometry:new(1, 1, 1),
    TL.MeshStandardMaterial:new{ color = 0xff8800 })

```

`PlaneGeometry` лежит в плоскости XY и смотрит в сторону +Z (как и в three.js). Чтобы сделать из неё пол, поверните её: `mesh:rotateX(-math.pi / 2)`.

### Объекты

`Mesh` `SkinnedMesh` `Skeleton` `InstancedMesh` `LOD`

Для работы `LOD` не нужны правки в рендерере — он просто скрывает и показывает нужные объекты, а обход сцены это учитывает. Вызывайте `lod:update(camera)` вручную рядом с `controls:update`, так как рендерер не ищет их сам:

```lua
local lod = TL.LOD:new()
lod:addLevel(highDetail, 0)
lod:addLevel(lowDetail, 25)

```

`InstancedMesh` повторяет интерфейс three.js, но **не** объединяет отрисовку в один draw call — подробнее в разделе [Ограничения](https://www.google.com/search?q=%23%D0%BE%D0%B3%D1%80%D0%B0%D0%BD%D0%B8%D1%87%D0%B5%D0%BD%D0%B8%D1%8F). Индексация начинается с 1, как и везде в Lua.

### Материалы

`Material` `MeshStandardMaterial`

Затенение работает по схеме Metallic-Roughness PBR (модель Кука-Торренса, распределение GGX, геометрия Смита и Френель Шлика). Параметры `metalness`, `roughness`, `emissive`, `normalMap`, `aoMap` и встроенная карта metallic-roughness из glTF корректно пробрасываются в шейдер:

```lua
local m = TL.MeshStandardMaterial:new{ color = 0xc84a3a, metalness = 0, roughness = 0.35 }
m.emissive:set(0x220800)

```

Если у модели нет карты metallic-roughness, она считается матовым диэлектриком (`metalness = 0`, `roughness = 1`). Значения, прописанные без карты, игнорируются, потому что 3D-экспортеры любят вшивать их наугад (например, Mixamo ставит 0.5/0.5 на все материалы подряд, из-за чего кожа персонажей становилась бы полуметаллической). Оба значения доступны как обычные поля, так что загруженный материал всегда можно донастроить вручную.

Картам нормалей не нужен атрибут касательной (tangent) — касательный базис высчитывается прямо во фрагментном шейдере через экранные производные, поэтому формат вершин остается чистым.

В движке есть два осознанных отступления от каноничного PBR (оба настраиваются):

* **Без карт окружения (Environment Probe).** Их роль выполняет ambient-свет: металлы отражают его с оттенком своего цвета, а диэлектрики просто рассеивают. Без этого трюка металл под единственным источником света выглядел бы почти черным — физически правильно, но на практике бесполезно.
* **Смягчение светотени (Wrapped Diffuse).** Параметр `renderer.diffuseWrap` (по умолчанию `0.25`) размывает границу тени, чтобы неосвещенные грани оставались читаемыми. Поставьте `0`, если нужен честный жесткий спад.

### Камеры

`Camera` `PerspectiveCamera` `OrthographicCamera`

### Источники света

`Light` `AmbientLight` `DirectionalLight` `PointLight` `SpotLight`

`PointLight` и `SpotLight` можно добавлять на сцену и настраивать, но дефолтный шейдер пока обрабатывает только один направленный свет (Directional) и фоновый (Ambient). Они добавлены для того, чтобы код, написанный под three.js, загружался без ошибок.

### Рендерер

`WebGLRenderer` — `render(scene, camera)`, `setClearColor`, `setSize`, `info.render`

За один обход сцены отрисовка разбивается на два пакета по типу шейдера: сначала статические меши, потом с костной анимацией. Благодаря этому переключение программ происходит всего раз за кадр. Внутри каждого пакета геометрия сортируется по `renderOrder`, затем непрозрачные объекты перед прозрачными, а далее по дистанции: от ближних к дальним для непрозрачных (чтобы Z-тест отсекал лишнее как можно раньше) и от дальних к ближним для прозрачных (как того требует блендинг).

Отсечение невидимых объектов (Frustum Culling) происходит во время этого же обхода по ограничивающей сфере геометрии. Анимированные меши не отсекаются: их сферы считаются по исходной позе, а при анимации персонаж легко может замахнуться рукой за её пределы. Отсечение можно выключить через `renderer.frustumCulling = false`, а в `info.render.culled` посмотреть статистику отброшенных объектов.

### Загрузчики

`GLTFLoader` `ColladaLoader` `TextureLoader` — `load(url, onLoad, onProgress, onError)`. Загрузчики моделей возвращают `{ scene, animations }`. Так как LÖVE читает файлы с диска synchronously, колбэк срабатывает сразу, но использовать результат через возвращаемое значение так же удобно.

### Анимация

`AnimationClip` `AnimationAction` `AnimationMixer`

Все активные анимации смешиваются по весам, поэтому `crossFadeTo` дает честный и плавный переход:

```lua
walk:play()
run:play()
walk:crossFadeTo(run, 0.4)

```

Если нужен более легкий вариант, поставьте `mixer.blending = false` — тогда анимация с наибольшим весом будет просто перебивать остальные.

### Управление

`FlyControls` — полеты на WASD/QE, обзор мышью, скорость на колесико.

`OrbitControls` — вращение левой кнопкой мыши, панорамирование правой, зум колесиком. В отличие от веб-версии, здесь нет DOM-дерева, поэтому события LÖVE нужно прокидывать вручную:

```lua
function love.update(dt)             controls:update(dt) end
function love.mousemoved(x,y,dx,dy)  controls:mousemoved(x, y, dx, dy) end
function love.wheelmoved(x,y)        controls:wheelmoved(y) end

```

Контроллер сам управляет позицией камеры, пересчитывая её относительно точки `target`. Если нужно сдвинуть камеру — двигайте `target`, а не `camera.position`.

## Отличия от three.js

**Вызов методов через двоеточие `:`.** Все методы принимают сам объект первым аргументом, поэтому даже статические функции из three.js здесь вызываются как методы: `clip:findByName(clips, name)`.

**Мутирующие методы получили суффикс.** Метод `Vector3:add` существовал в движке еще до появления фасада three.js и возвращал *новый* вектор, тогда как в three.js `add` меняет текущий. Чтобы они не конфликтовали, версии из three.js переименовали:

| three.js | здесь |
| --- | --- |
| `Vector3.add` / `.sub` | `addV` / `subV` |
| `Vector3.normalize` | `normalizeSelf` |
| `Vector3.lerp` | `lerpSelf` |
| `Vector3.min` / `.max` | `minSelf` / `maxSelf` |
| `Vector3.clamp` | `clampSelf` |
| `Vector3.floor` / `.ceil` / `.round` | `floorSelf` / `ceilSelf` / `roundSelf` |
| `Matrix4.transpose` | `transposeSelf` |

Все остальные методы (`set`, `copy`, `multiplyScalar`, `applyQuaternion`, `addScaledVector`, `crossVectors` и т.д.) сохранили оригинальные названия и мутирующее поведение из three.js.

## Ограничения

* Комплектный шейдер поддерживает только **один** направленный источник света и фоновую засветку. Если на сцене больше источников, движок выберет самый яркий направленный, просуммирует фоновый свет и предупредит об этом в консоли. `PointLight` и `SpotLight` пока не просчитываются.
* `InstancedMesh` не объединяет отрисовку в один draw call. Шейдер принимает только одну матрицу `u_model`, поэтому рендерер проходит по инстансам и рисует их по очереди. Экономия идет за счет общей геометрии, материала и границ. API полностью совпадает с three.js, так что когда мы это перепишем, ваш код менять не придется.
* Нет карт окружения и IBL, поэтому отражать нечего — смотрите обходной путь с фоновым светом в разделе «Материалы».
* Вычисление касательных работает точно везде, где UV-развертка локально аффинна (то есть практически везде, кроме намеренно растянутых текстур).
* `Raycaster` проверяет анимированные меши по их **исходной позе (bind pose)**: он считывает вершины до того, как их деформирует GPU. Выбор движущегося персонажа мышью будет приблизительным.
* Генераторы геометрии считают форму выпуклой относительно центра: грани сворачиваются наружу путем сравнения с их центроидом. `TorusGeometry` — единственное исключение, так как у тора есть внутренняя стенка. Неполные фигуры (где `thetaLength` меньше полного оборота) могут получиться вывернутыми наизнанку; если это произошло, укажите им `side = "double"`.
* Класса `Texture` нет — объект `Image` в LÖVE уже содержит настройки фильтрации и повторения, которые three.js держит отдельно.
* Скелеты ограничены 128 костями (лимит `MAX_BONES` в шейдере).

## Шейдеры

LÖVE собирает шейдеры из обычных строк, поэтому варианты — это просто разные комбинации кусков кода. Файлы в `shader/parts/` содержат GLSL-код, разложенный по слотам, а `shader/init.lua` собирает их в итоговый шейдер.

Код разделен по **фичам**, а не по стадиям pipeline: вся логика скиннинга лежит в одном файле (и вершинные юниформы, и сама математика). Разделение по стадиям заставило бы разбросать одну фичу по разным файлам и усложнило бы правки.

Компилируется два варианта шейдера: `static` (статичный) и `skinned` (анимированный). Это сделано не для красоты: массив на 128 костей забирает 2048 вершинных юниформ при гарантированном минимуме в 1024, поэтому статичные меши не должны его даже объявлять.
