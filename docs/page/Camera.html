Camera

Extends Object3D, inherits its API. Adds the two matrices the renderer needs: projectionMatrix, filled in by a subclass, and matrixWorldInverse — the view matrix, kept as the inverse of wherever the camera sits in the scene graph.

Methods

.isCamera()

Returns true.

.updateMatrixWorld(force)

Calls Object3D.updateMatrixWorld, then recomputes matrixWorldInverse from the new matrixWorld.

.updateWorldMatrix(updateParents, updateChildren)

Same idea as .updateMatrixWorld, following the parents/children propagation rules of Object3D.updateWorldMatrix.

.getWorldDirection(target)

Where the camera looks: down its own -Z, in world space.

.viewProjectionMatrix(target)

projectionMatrix * matrixWorldInverse, the single matrix the bundled shader takes as u_viewProj. Not part of three.js's API — three.js sends projection and view separately — but the shader wants them premultiplied.

.worldToScreen(v, width, height)

Converts a world-space point to pixel coordinates for a width×height viewport (defaults to the LÖVE window's own dimensions). Internally clones v, calls Vector3:project(self) to get NDC, then maps NDC [-1, 1] onto pixels — flipping Y, since NDC's +Y is up and LÖVE's +Y is down. Returns three values: x, y, visible, where visible is false when the point's NDC z falls outside [-1, 1] — i.e. it's behind the camera or past the far plane, the same test three.js's frustum check makes.

.screenToWorld(x, y, width, height, ndcZ)

The inverse: pixel coordinates (plus an optional NDC depth, ndcZ, defaulting to 0 — mid-frustum) to a world-space point. Maps the pixel onto NDC, then calls Vector3:unproject(self).

.copy(source, recursive)

Differences from three.js

  • .viewProjectionMatrix(target) is a TreeLua-only facade with no three.js equivalent, added because the shader wants projection and view premultiplied into one matrix.
  • .worldToScreen(v, width, height) and .screenToWorld(x, y, width, height, ndcZ) have no three.js equivalent — the browser DOM already gives three.js code pixel coordinates, so three.js users convert to/from NDC directly with Vector3.project/.unproject. LÖVE has no DOM, so this facade exists to do the pixel math (and the Y flip) in one place instead of at every call site.

Camera

Наследует Object3D, наследует её API. Добавляет две матрицы, необходимые рендереру: projectionMatrix, заполняемую подклассом, и matrixWorldInverse — матрицу вида, хранимую как обратную к тому, где камера находится в графе сцены.

Methods

.isCamera()

Возвращает true.

.updateMatrixWorld(force)

Вызывает Object3D.updateMatrixWorld, затем пересчитывает matrixWorldInverse из нового matrixWorld.

.updateWorldMatrix(updateParents, updateChildren)

Та же идея, что и .updateMatrixWorld, следуя правилам распространения parents/children из Object3D.updateWorldMatrix.

.getWorldDirection(target)

Куда смотрит камера: вдоль своей собственной -Z, в мировом пространстве.

.viewProjectionMatrix(target)

projectionMatrix * matrixWorldInverse — единая матрица, которую встроенный шейдер принимает как u_viewProj. Не входит в API three.js — three.js отправляет projection и view отдельно — но шейдеру нужны они перемноженными заранее.

.worldToScreen(v, width, height)

Переводит точку мирового пространства в пиксельные координаты для вьюпорта width×height (по умолчанию — размеры самого окна LÖVE). Внутри клонирует v, вызывает Vector3:project(self), чтобы получить NDC, затем отображает NDC [-1, 1] на пиксели — с переворотом по Y, так как +Y в NDC смотрит вверх, а +Y в LÖVE — вниз. Возвращает три значения: x, y, visible, где visible равен false, когда z точки в NDC выходит за пределы [-1, 1] — то есть точка позади камеры или за дальней плоскостью, та же проверка, что делает frustum-тест three.js.

.screenToWorld(x, y, width, height, ndcZ)

Обратная операция: пиксельные координаты (плюс необязательная глубина в NDC, ndcZ, по умолчанию 0 — середина фрустума) в точку мирового пространства. Отображает пиксель на NDC, затем вызывает Vector3:unproject(self).

.copy(source, recursive)

Differences from three.js

  • .viewProjectionMatrix(target) — фасад, существующий только в TreeLua, без аналога в three.js, добавлен потому что шейдеру нужны projection и view, перемноженные в одну матрицу заранее.
  • .worldToScreen(v, width, height) и .screenToWorld(x, y, width, height, ndcZ) не имеют аналога в three.js — DOM браузера уже даёт коду three.js пиксельные координаты, так что пользователи three.js конвертируют в/из NDC напрямую через Vector3.project/.unproject. В LÖVE нет DOM, поэтому этот фасад существует, чтобы делать пиксельную математику (и переворот по Y) в одном месте, а не в каждой точке вызова.
