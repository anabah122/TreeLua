InstancedMesh

One geometry drawn at many transforms. Extends Mesh (and through it Object3D) and inherits their APIs. The surface is three.js's, including the 1-based index (three.js counts instances from 0; everything else in this engine counts from 1, and mixing the two conventions inside one library would be worse than the small divergence).

local field = InstancedMesh:new(geometry, material, 200)
local m = Matrix4:new()
for i = 1, 200 do
    m:makeTranslation(i % 20, 0, math.floor(i / 20))
    field:setMatrixAt(i, m)
end
scene:add(field)

Constructor

InstancedMesh(geometry, material, count)

count defaults to 0. Allocates count identity matrices up front.

Properties

PropertyTypeDefaultDescription
countnumber0Number of instances.
instanceMatrixtable{}Array of Matrix4, one per instance (1-based).
instanceColortablenilSparse array of Color, created lazily by setColorAt.

Also inherits .geometry, .material from Mesh.

Methods

.isInstancedMesh()

Returns true.

.getMatrixAt(index, target)

.setMatrixAt(index, matrix)

No-op if index is out of [1, count].

.getColorAt(index, target)

.setColorAt(index, color)

No-op if index is out of [1, count]. Allocates .instanceColor on first use.

.setCount(count)

Grows or shrinks the instance set. New slots get an identity matrix rather than nil, so the renderer never has to test for a hole.

.copy(source, recursive)

Extends Mesh.copy; deep-copies instanceMatrix and, if present, instanceColor.

.dispose()

Drops instanceMatrix and instanceColor.

Differences from three.js

  • 1-based instance indices, unlike three.js which counts from 0.
  • Not one draw call for the whole set. The bundled shader takes a single u_model uniform, so the renderer walks the instances and issues one draw per instance — the saving is in the shared geometry, material and bounds, not in the draw-call count. True GPU instancing (three.js's actual behaviour) would require an instance-attribute shader path this engine doesn't have yet.
  • No instanceMatrix.needsUpdate / instanceColor.needsUpdate dirty flags — there is no GPU buffer to re-upload, so writes take effect immediately.
  • No boundingBox/boundingSphere specific to the instanced set, and no toJSON.

InstancedMesh

Одна геометрия, отрисованная со множеством трансформов. Наследует Mesh (а через него Object3D) и получает их API. Поверхность соответствует three.js, включая индекс с отсчётом от 1 (three.js считает инстансы с 0; всё остальное в этом движке считает с 1, и смешивание двух конвенций внутри одной библиотеки было бы хуже, чем это небольшое расхождение).

local field = InstancedMesh:new(geometry, material, 200)
local m = Matrix4:new()
for i = 1, 200 do
    m:makeTranslation(i % 20, 0, math.floor(i / 20))
    field:setMatrixAt(i, m)
end
scene:add(field)

Constructor

InstancedMesh(geometry, material, count)

count по умолчанию 0. Заранее выделяет count единичных матриц.

Properties

СвойствоТипПо умолчаниюОписание

instanceMatrixtable{}Массив Matrix4, по одной на инстанс (отсчёт от 1).
instanceColortablenilРазреженный массив Color, создаётся лениво в setColorAt.

Также наследует .geometry, .material от Mesh.

Methods

.isInstancedMesh()

Возвращает true.

.getMatrixAt(index, target)

.setMatrixAt(index, matrix)

Ничего не делает, если index вне диапазона [1, count].

.getColorAt(index, target)

.setColorAt(index, color)

Ничего не делает, если index вне диапазона [1, count]. Выделяет .instanceColor при первом использовании.

.setCount(count)

Увеличивает или уменьшает набор инстансов. Новые слоты получают единичную матрицу, а не nil, поэтому рендереру никогда не нужно проверять наличие дыры.

.copy(source, recursive)

Расширяет Mesh.copy; глубоко копирует instanceMatrix и, если есть, instanceColor.

.dispose()

Сбрасывает instanceMatrix и instanceColor.

Differences from three.js

  • Индексы инстансов с отсчётом от 1, в отличие от three.js, где отсчёт от 0.
  • Не один draw call на весь набор. Встроенный шейдер принимает единственный uniform u_model, поэтому рендерер проходит по инстансам и делает один draw на каждый — выигрыш в общих геометрии, материале и границах, а не в количестве draw call'ов. Настоящий GPU-инстансинг (реальное поведение three.js) потребовал бы шейдерного пути с инстанс-атрибутами, которого в этом движке пока нет.
  • Нет флагов "грязности" instanceMatrix.needsUpdate / instanceColor.needsUpdate — тут нет GPU-буфера, который надо перезагружать, поэтому записи вступают в силу немедленно.
  • Нет специфичных для набора инстансов boundingBox/boundingSphere, и нет toJSON.
