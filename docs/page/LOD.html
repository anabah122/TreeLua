LOD

Swap detail with distance. Extends Object3D and inherits its full API. Every level is a child, so the whole set inherits the LOD's transform; only one is left visible at a time, which is what the renderer's traverseVisible walk then picks up — there is no special case in the renderer for this.

local lod = LOD:new()
lod:addLevel(highMesh, 0)
lod:addLevel(lowMesh, 25)
scene:add(lod)
-- each frame:
lod:update(camera)

Constructor

LOD()

Properties

PropertyTypeDefaultDescription
levelstable{}Array of { distance, hysteresis, object }, kept sorted by distance.
autoUpdatebooleantrueKept for signature compatibility; not read by the renderer — see below.

Otherwise inherits all of Object3D's properties.

Methods

.isLOD()

Returns true.

.addLevel(object, distance, hysteresis)

Adds object as a child at the given distance (absolute value, defaults 0) and inserts it into .levels in sorted order. hysteresis defaults to 0 and widens the switch threshold in the direction already taken, so a camera hovering on a boundary does not flicker between two levels.

.removeLevel(distance)

Removes the level at exactly distance and its child. Returns whether one was found.

.getCurrentLevel()

Returns the index into .levels last chosen by .update(), or 1 if it hasn't run yet.

.getObjectForDistance(distance)

Returns which level's object would be shown at the given distance, applying hysteresis, without changing visibility.

.update(camera)

Picks the level for the camera's current world position and sets visible on every level's object accordingly (only the chosen one is visible). Must be called by the application, typically next to controls:update — see Differences.

.copy(source, recursive)

Extends Object3D.copy (called non-recursively); rebuilds .levels by cloning each level's object.

Differences from three.js

  • No automatic per-frame update. three.js updates levels from inside its render loop (WebGLRenderer.render calls lod.update(camera) for every LOD it encounters). This renderer does not know about LOD objects at all, so update(camera) must be called explicitly by the application each frame. autoUpdate is kept on the object for signature compatibility but is not read anywhere.

LOD

Смена уровня детализации в зависимости от расстояния. Наследует Object3D и получает весь его API. Каждый уровень — это ребёнок, поэтому весь набор наследует трансформ LOD; видимым остаётся только один за раз, что и подхватывает обход traverseVisible рендерера — специального случая для этого в рендерере нет.

local lod = LOD:new()
lod:addLevel(highMesh, 0)
lod:addLevel(lowMesh, 25)
scene:add(lod)
-- each frame:
lod:update(camera)

Constructor

LOD()

Properties

СвойствоТипПо умолчаниюОписание
levelstable{}Массив { distance, hysteresis, object }, поддерживается отсортированным по расстоянию.
autoUpdatebooleantrueХранится для совместимости сигнатуры; рендерером не читается — см. ниже.

В остальном наследует все свойства Object3D.

Methods

.isLOD()

Возвращает true.

.addLevel(object, distance, hysteresis)

Добавляет object как ребёнка на заданном distance (абсолютное значение, по умолчанию 0) и вставляет его в .levels в отсортированном порядке. hysteresis по умолчанию 0 и расширяет порог переключения в уже выбранном направлении, так что камера, зависшая на границе, не мерцает между двумя уровнями.

.removeLevel(distance)

Удаляет уровень ровно на distance и его ребёнка. Возвращает, был ли найден такой уровень.

.getCurrentLevel()

Возвращает индекс в .levels, последним выбранный .update(), либо 1, если он ещё не запускался.

.getObjectForDistance(distance)

Возвращает, объект какого уровня был бы показан на заданном расстоянии, с учётом гистерезиса, не меняя видимость.

.update(camera)

Выбирает уровень для текущей мировой позиции камеры и соответствующим образом выставляет visible на объекте каждого уровня (видимым остаётся только выбранный). Должен вызываться приложением, обычно рядом с controls:update — см. Differences.

.copy(source, recursive)

Расширяет Object3D.copy (вызывается нерекурсивно); перестраивает .levels, клонируя объект каждого уровня.

Differences from three.js

  • Нет автоматического обновления каждый кадр. three.js обновляет уровни изнутри своего цикла рендеринга (WebGLRenderer.render вызывает lod.update(camera) для каждого встреченного LOD). Этот рендерер вообще не знает об объектах LOD, поэтому update(camera) должен явно вызываться приложением каждый кадр. autoUpdate сохранён на объекте для совместимости сигнатуры, но нигде не читается.

Source: three/objects/LOD.lua
