Skeleton

Joints plus their inverse bind matrices. In three.js a Skeleton holds an array of Bone objects. Here it wraps the importer's flat node list and skin record instead, because that is what the animation sampler writes into and what importer.common.palette reads. Wrapping rather than converting keeps one source of truth: animation writes to nodes, the palette reads from nodes, no copy in between to fall stale.

Constructor

Skeleton(nodes, skin)

nodes is the importer's flat node list ({ [i] = { name, parent, children, localMatrix, worldMatrix, ... } }). skin is { joints = {node indices}, inverseBind = {mat4}, skeletonRoot }. Does not extend Object3D — a Skeleton is data, not a scene graph node.

Properties

PropertyTypeDefaultDescription
typestring"Skeleton"
nodestable—Flat importer node list.
skintable—Joint indices and inverse bind matrices.

Methods

.isSkeleton()

Returns true.

.getBoneCount()

Returns #skin.joints, or 0 if there is no skin.

.getBoneByName(name)

Scans .nodes for a matching name. three.js exposes bones by name too, but as an array lookup — here the node list is flat, so this is a linear scan.

.update(root)

Recomputes every node's world matrix from its local one. The animation mixer calls this after sampling; root seeds the root matrices so a model transform can be baked in (defaults to nodes.rootMatrix).

.computeBoneMatrices()

Returns the bone palette for the current pose via importer.common.palette, or nil if there is no skin.

.clone()

Deep-copies the live half only — each node's transform (translation/rotation/scale, localMatrix, worldMatrix) — which is what an AnimationMixer writes into every frame. Hierarchy shape (parent/children links), skin.inverseBind, joint indices, and the owning mesh's geometry/material all stay shared by reference with the source skeleton — the same split three.js's SkeletonUtils.clone makes: share geometry, give each instance its own bones. That split is what lets N animated instances of one model exist without N re-parses of the source file — see Model.

Differences from three.js

  • No Bone objects. three.js's Skeleton is an array of Bone (an Object3D subclass) plus a parallel boneInverses array. TreeLua instead wraps the importer's flat node table directly, so bones are plain node records, not scene-graph objects you can :add() children to independently.
  • No .bones / .boneInverses properties — use .nodes and .skin.inverseBind.
  • .clone() has no direct three.js counterpart on Skeleton itself — three.js clones a rig through the separate SkeletonUtils addon, which walks and duplicates Bone objects. Here it's a plain method, since there are no scene-graph bone objects to walk.

TreeLua / Objects

Skeleton

Суставы (joints) плюс их обратные bind-матрицы. В three.js Skeleton хранит массив объектов Bone. Здесь же он вместо этого оборачивает плоский список узлов импортёра и запись skin, потому что именно в них пишет сэмплер анимации и именно их читает importer.common.palette. Обёртывание вместо преобразования сохраняет единый источник истины: анимация пишет в узлы, палитра читает из узлов, между ними нет копии, которая могла бы устареть.

Constructor

Skeleton(nodes, skin)

nodes — это плоский список узлов импортёра ({ [i] = { name, parent, children, localMatrix, worldMatrix, ... } }). skin — это { joints = {node indices}, inverseBind = {mat4}, skeletonRoot }. Не наследует Object3D — Skeleton это данные, а не узел графа сцены.

Properties

СвойствоТипПо умолчаниюОписание
typestring"Skeleton"
nodestable—Плоский список узлов импортёра.
skintable—Индексы суставов и обратные bind-матрицы.

Methods

.isSkeleton()

Возвращает true.

.getBoneCount()

Возвращает #skin.joints, либо 0, если скина нет.

.getBoneByName(name)

Сканирует .nodes в поисках совпадающего имени. three.js тоже даёт доступ к костям по имени, но через поиск по массиву — здесь список узлов плоский, поэтому это линейный перебор.

.update(root)

Пересчитывает мировую матрицу каждого узла из его локальной. Миксер анимации вызывает это после сэмплирования; root задаёт начальные корневые матрицы, чтобы можно было запечь трансформ модели (по умолчанию nodes.rootMatrix).

.computeBoneMatrices()

Возвращает палитру костей для текущей позы через importer.common.palette, либо nil, если скина нет.

.clone()

Глубоко копирует только «живую» половину — трансформ каждого узла (translation/rotation/scale, localMatrix, worldMatrix), то есть именно то, что каждый кадр записывает AnimationMixer. Форма иерархии (связи parent/children), skin.inverseBind, индексы суставов и геометрия/материал владеющего меша остаются общими по ссылке с исходным скелетом — то же разделение, что делает SkeletonUtils.clone в three.js: делить геометрию, но дать каждому инстансу свои кости. Именно это разделение позволяет существовать N анимированным инстансам одной модели без N повторных парсингов исходного файла — см. Model.

Differences from three.js

  • Нет объектов Bone. Skeleton в three.js — это массив Bone (подкласс Object3D) плюс параллельный массив boneInverses. TreeLua вместо этого напрямую оборачивает плоскую таблицу узлов импортёра, так что кости — это обычные записи узлов, а не объекты графа сцены, которым можно независимо :add() детей.
  • Нет свойств .bones / .boneInverses — используйте .nodes и .skin.inverseBind.
  • .clone() не имеет прямого аналога у three.js-класса Skeleton — three.js клонирует риг через отдельный аддон SkeletonUtils, который обходит и дублирует объекты Bone. Здесь это обычный метод, так как нет объектов костей в графе сцены, которые нужно было бы обходить.
