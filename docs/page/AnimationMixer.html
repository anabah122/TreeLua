TreeLua / Animation

AnimationMixer

Plays and blends AnimationClips against a target object's skeleton or scene graph. By default the mixer accumulates every enabled, non-zero-weight AnimationAction through an internal PoseAccumulator each frame — translation and scale blend linearly and rotation blends via quaternion slerp (with hemisphere selection) — so multiple simultaneously-playing clips combine the way three.js's mixer does, instead of only the highest-weight clip winning.

Constructor

AnimationMixer.new(root)

Creates a mixer bound to a root object (typically a skinned mesh or its skeleton root). Actions created from this mixer animate that root's bones/nodes by name.

Properties

PropertyTypeDefaultDescription
rootObject3D—Object whose hierarchy the mixer animates.
blendingbooleantrueWhen true (default), every frame accumulates all enabled actions with weight > 0 through the PoseAccumulator. Set to false to fall back to the legacy single-clip path, which samples only the action with the highest weight and applies it directly — cheaper, but loses the ability to cross-blend multiple simultaneous clips.
actionstable{}Cache of AnimationAction instances keyed by clip, populated by clipAction.

Methods

:clipAction(clip)

Returns the AnimationAction for clip on this mixer, creating and caching it on first call.

:update(delta)

Advances every action's time by delta, then applies the resulting pose to root. When blending is true this runs all enabled actions with non-zero weight through the PoseAccumulator and writes the combined pose; when blending is false it samples only the single highest-weight enabled action and applies it directly.

:stopAllAction()

Stops every action created on this mixer.

Differences from three.js

  • Exposes a blending flag with no three.js equivalent: it toggles between the default multi-action accumulation path (matching three.js's per-frame blending behavior) and a legacy single-clip path retained for cheaper playback when only one clip is ever active.
  • No AnimationObjectGroup support, time-scale-on-mixer, or clip-event listeners (finished/loop).

TreeLua / Animation

AnimationMixer

Воспроизводит и смешивает AnimationClip относительно скелета или графа сцены целевого объекта. По умолчанию миксер каждый кадр накапливает все включённые AnimationAction с ненулевым весом через внутренний PoseAccumulator — translation и scale смешиваются линейно, а rotation — через кватернионный slerp (с выбором полушария) — так что несколько одновременно проигрывающихся клипов комбинируются так же, как это делает миксер three.js, а не так, что побеждает только клип с наибольшим весом.

Constructor

AnimationMixer.new(root)

Создаёт миксер, привязанный к корневому объекту (обычно skinned mesh или корню его скелета). Экшены, созданные этим миксером, анимируют кости/узлы этого корня по имени.

Properties

СвойствоТипПо умолчаниюОписание
rootObject3D—Объект, чью иерархию анимирует миксер.
blendingbooleantrueЕсли true (по умолчанию), каждый кадр все включённые экшены с весом > 0 накапливаются через PoseAccumulator. Установите false, чтобы вернуться к устаревшему пути с одним клипом, который сэмплирует только экшен с наибольшим весом и применяет его напрямую — дешевле, но теряется возможность кросс-смешивания нескольких одновременных клипов.
actionstable{}Кэш экземпляров AnimationAction, индексированный по клипу, заполняется через clipAction.

Methods

:clipAction(clip)

Возвращает AnimationAction для clip на этом миксере, создавая и кэшируя его при первом вызове.

:update(delta)

Продвигает время каждого экшена на delta, затем применяет полученную позу к root. Когда blending равен true, это прогоняет все включённые экшены с ненулевым весом через PoseAccumulator и записывает объединённую позу; когда blending равен false, сэмплируется только один включённый экшен с наибольшим весом и применяется напрямую.

:stopAllAction()

Останавливает все экшены, созданные на этом миксере.

Differences from three.js

  • Предоставляет флаг blending, не имеющий аналога в three.js: он переключает между стандартным путём накопления нескольких экшенов (соответствующим поведению покадрового смешивания в three.js) и устаревшим путём с одним клипом, сохранённым ради более дешёвого воспроизведения, когда активен только один клип.
  • Нет поддержки AnimationObjectGroup, масштаба времени на уровне миксера или слушателей событий клипа (finished/loop).
