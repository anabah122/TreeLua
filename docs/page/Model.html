Model

The asset, loaded once, used by any number of game objects. Not a three.js class, and not a scene-graph node — it exists because a loaded file and a live game object are different things. Geometry, material and the joint hierarchy/inverse-bind matrices describe the asset once and never change per spawn — the static half. Position/rotation/scale, the current animation pose and which clip is playing belong to whichever game object is using the model right now — the dynamic half, and there can be any number of them live at once against one loaded Model.

local model = Model:fromLoaderResult(TL.GLTFLoader:new():load(MODEL_PATH))
local enemy = model:createInstance()   -- cheap: no file I/O, no re-parse
scene:add(enemy.scene)
enemy.mixer:clipAction(enemy.animations[1]):play()
enemy.scene.position:set(x, 0, z)

Constructor

Model(scene, animations, userData)

Ordinary code does not call this directly — use :fromLoaderResult(). scene is the root Object3D of the loaded asset, animations an array of AnimationClip.

Properties

PropertyTypeDefaultDescription
typestring"Model"
sceneObject3D—The asset's own root, as returned by a loader. Never added to a rendered scene directly — every live use goes through :createInstance().
animationsAnimationClip[]{}The asset's clips, shared read-only across all instances.
userDatatable—Passed through from the loader result.

Methods

:isModel()

Returns true. Type-check facade.

:fromLoaderResult(result)

Wraps whatever a loader handed back: { scene, animations, userData } (as returned by GLTFLoader or ColladaLoader). This is the normal way to build a Model.

:createInstance()

One live, independently animatable use of this model: its own transform, its own skeleton pose, its own AnimationMixer. Returns { scene, animations, mixer }.

Never clones geometry, materials, or the source love.Mesh objects — those are read straight off the model's own Mesh/SkinnedMesh instances by reference, same as three.js sharing a BufferGeometry across copies. What is per instance: a fresh Object3D shell for every primitive in the source hierarchy (so each has its own matrixWorld to draw at), and — for skinned primitives — one shared cloned Skeleton holding just the current pose (joints/inverse-bind still point at the model's own skin data; see Skeleton.clone()). All skinned primitives in one source file share a single skeleton (they're rigged to the same skin), so one clone covers however many skinned meshes the model has. The returned animations are the model's own clips retargeted onto that cloned skeleton's nodes via AnimationClip.withNodes(), so playing them animates this instance and no other.

That split — parse the file once, spawn shells cheaply — is what makes N animated instances of one model affordable.

Differences from three.js

  • No three.js equivalent. three.js code typically calls object.clone() on a loaded scene root per spawn, or reaches for the separate SkeletonUtils.clone addon for skinned rigs. Model exists because this engine treats "the loaded asset" and "one live use of it" as two distinct concerns instead of leaning on generic Object3D.clone(), which would deep-copy the whole hierarchy (and, for a skinned mesh, share one skeleton across every clone unless the caller remembers to fix that up by hand).
  • Not an Object3D — a Model itself is never added to a scene. Only what :createInstance() returns (.scene) is.

Model

Ассет, загружаемый один раз и используемый любым числом игровых объектов. Не класс three.js и не узел графа сцены — существует потому, что загруженный файл и живой игровой объект — разные вещи. Геометрия, материал и иерархия суставов/обратные bind-матрицы описывают ассет один раз и никогда не меняются на спавн — статичная половина. Position/rotation/scale, текущая поза анимации и то, какой клип играет, принадлежат тому игровому объекту, который сейчас использует модель — динамическая половина, и их может быть живо любое число одновременно против одной загруженной Model.

local model = Model:fromLoaderResult(TL.GLTFLoader:new():load(MODEL_PATH))
local enemy = model:createInstance()   -- дёшево: без чтения файла, без повторного парсинга
scene:add(enemy.scene)
enemy.mixer:clipAction(enemy.animations[1]):play()
enemy.scene.position:set(x, 0, z)

Constructor

Model(scene, animations, userData)

Обычный код не вызывает это напрямую — используйте :fromLoaderResult(). scene — корневой Object3D загруженного ассета, animations — массив AnimationClip.

Properties

СвойствоТипПо умолчаниюОписание
typestring"Model"
sceneObject3D—Собственный корень ассета, как его вернул загрузчик. Никогда не добавляется в рендеримую сцену напрямую — каждое живое использование идёт через :createInstance().
animationsAnimationClip[]{}Клипы ассета, общие только для чтения между всеми инстансами.

Methods

:isModel()

Возвращает true. Фасад проверки типа.

:fromLoaderResult(result)

Оборачивает то, что вернул загрузчик: { scene, animations, userData } (как возвращает GLTFLoader или ColladaLoader). Обычный способ построить Model.

:createInstance()

Одно живое, независимо анимируемое использование этой модели: свой трансформ, своя поза скелета, свой AnimationMixer. Возвращает { scene, animations, mixer }.

Никогда не клонирует геометрию, материалы или исходные объекты love.Mesh — они читаются прямо с собственных инстансов Mesh/SkinnedMesh модели по ссылке, так же как three.js делит BufferGeometry между копиями. Что действительно своё для инстанса: свежий Object3D-shell на каждый примитив исходной иерархии (у каждого свой matrixWorld для отрисовки), и — для скиннированных примитивов — один общий клонированный Skeleton, хранящий только текущую позу (joints/inverse-bind по-прежнему указывают на собственные skin-данные модели; см. Skeleton.clone()). Все скиннированные примитивы в одном исходном файле делят один скелет (они привязаны к одному skin), так что одного клонирования хватает на любое число скиннированных мешей модели. Возвращаемые animations — это собственные клипы модели, ретаргетированные на узлы этого клонированного скелета через AnimationClip.withNodes(), так что их воспроизведение анимирует именно этот инстанс и никакой другой.

Именно это разделение — распарсить файл один раз, дёшево спавнить shell'ы — делает доступными N анимированных инстансов одной модели.

Differences from three.js

  • Нет аналога в three.js. Код на three.js обычно вызывает object.clone() на корне загруженной сцены на каждый спавн, либо использует отдельный аддон SkeletonUtils.clone для скиннированных ригов. Model существует потому, что этот движок трактует «загруженный ассет» и «одно живое использование его» как два разных понятия вместо опоры на обобщённый Object3D.clone(), который глубоко скопировал бы всю иерархию (а для скиннированного меша — разделил бы один скелет между всеми клонами, если вызывающий код не исправит это вручную).
  • Не Object3D — сама Model никогда не добавляется в сцену. В сцену добавляется только то, что вернул :createInstance() (.scene).
