Raycaster

Picking against scene geometry.

local caster = Raycaster:new()
caster:setFromCamera({ x = ndcX, y = ndcY }, camera)
local hits = caster:intersectObjects(scene.children, true)
if hits[1] then print(hits[1].object.name, hits[1].distance) end

Each hit is { distance, point, object, face, faceIndex, uv }, ordered nearest first, as in three.js.

Constructor

Raycaster(origin, direction, near, far)

All arguments optional. Builds a Ray from origin/direction; near defaults to 0, far to math.huge.

Methods

.isRaycaster()

Returns true.

.set(origin, direction)

.setFromCamera(coords, camera)

coords carries normalised device coordinates, both components in [-1, 1] with +Y up, matching three.js. Handles both perspective (origin at the eye) and orthographic (parallel rays, origin slides across the near plane) cameras.

.setFromScreen(x, y, camera, width, height)

Facade over setFromCamera for the coordinates LÖVE actually hands a love.mousepressed handler: pixels, Y growing downward. width/height default to love.graphics.getWidth/Height().

.intersectMesh(object, hits)

Tests one mesh's triangles. The ray is pulled into the mesh's local space rather than pushing every vertex into world space. Rejects early against the geometry's bounding sphere. Respects material.visible and material.side (backface culling unless side ~= "front"). Appends hits to hits and returns it.

.intersectObject(object, recursive, hits)

Tests one object (and, unless recursive == false, its descendants), skipping invisible objects. Result is sorted nearest first.

.intersectObjects(objects, recursive, hits)

Same as intersectObject over an array of objects.

Differences from three.js

  • Skinned meshes are tested against their bind pose. The vertex tables held by BufferGeometry are the pre-skinning data — deformation happens on the GPU — so a moving character picks roughly, not exactly.
  • .setFromScreen(x, y, camera, width, height) has no three.js equivalent: WebGLRenderer knows its own canvas size, so three.js examples normalise screen coordinates by hand. A LÖVE mousepressed handler only has pixels, so that conversion lives here instead.
  • Only Mesh objects are testable; there is no Points/Line/Sprite intersection support.

Raycaster

Выбор объектов по геометрии сцены (picking).

local caster = Raycaster:new()
caster:setFromCamera({ x = ndcX, y = ndcY }, camera)
local hits = caster:intersectObjects(scene.children, true)
if hits[1] then print(hits[1].object.name, hits[1].distance) end

Каждое попадание — это { distance, point, object, face, faceIndex, uv }, отсортированные от ближайшего, как в three.js.

Constructor

Raycaster(origin, direction, near, far)

Все аргументы необязательны. Строит Ray из origin/direction; near по умолчанию 0, far — math.huge.

Methods

.isRaycaster()

Возвращает true.

.set(origin, direction)

.setFromCamera(coords, camera)

coords несёт нормализованные координаты устройства, оба компонента в [-1, 1] с +Y вверх, как в three.js. Обрабатывает и перспективные (origin в глазе камеры), и ортографические (параллельные лучи, origin скользит по ближней плоскости) камеры.

.setFromScreen(x, y, camera, width, height)

Фасад над setFromCamera для координат, которые LÖVE реально передаёт обработчику love.mousepressed: пиксели, Y растёт вниз. width/height по умолчанию — love.graphics.getWidth/Height().

.intersectMesh(object, hits)

Тестирует треугольники одного меша. Луч переводится в локальное пространство меша, а не каждая вершина — в мировое. Ранний отсев по ограничивающей сфере геометрии. Учитывает material.visible и material.side (отсечение задних граней, если side ~= "front"). Добавляет попадания в hits и возвращает его.

.intersectObject(object, recursive, hits)

Тестирует один объект (и, если не recursive == false, его потомков), пропуская невидимые объекты. Результат отсортирован от ближайшего.

.intersectObjects(objects, recursive, hits)

То же, что intersectObject, но по массиву объектов.

Differences from three.js

  • Скиннированные меши тестируются в bind pose. Таблицы вершин, хранимые BufferGeometry, — это данные до скиннинга, деформация происходит на GPU — поэтому выбор движущегося персонажа приблизительный, а не точный.
  • У .setFromScreen(x, y, camera, width, height) нет аналога в three.js: WebGLRenderer знает размер собственного canvas, поэтому примеры three.js нормализуют экранные координаты вручную. У обработчика mousepressed в LÖVE есть только пиксели, поэтому это преобразование живёт здесь.
  • Тестировать можно только объекты Mesh; нет поддержки пересечения с Points/Line/Sprite.
