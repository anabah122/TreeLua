SkinnedMesh

A Mesh deformed by a skeleton. Extends Mesh (and through it Object3D) and inherits their APIs. The palette maths lives in importer.common and is shared with the raw importer path; this class only decides which nodes to read and caches the resulting matrices for the renderer.

local mesh = SkinnedMesh:new(geometry, material)
mesh:bind(skeleton)

Constructor

SkinnedMesh(geometry, material)

Properties

PropertyTypeDefaultDescription
skeletonSkeletonnilSet by .bind().
bindMatrixMatrix4nilSet by .bind() when a matrix is passed.
bindMatrixInverseMatrix4nilInverse of bindMatrix, computed in .bind().

Also inherits .geometry, .material, .skin, .bindShapeMatrix from Mesh.

Methods

.isSkinnedMesh()

Returns true.

.bind(skeleton, bindMatrix)

Attaches a Skeleton. If bindMatrix is given, also stores it and its inverse.

.palette()

Returns the array of bone matrices for this frame, or nil if there is no bound skeleton with a skin. The skeleton owns the node list, so the palette follows whatever the animation mixer last wrote into it. If bindShapeMatrix is set (Collada), it is multiplied onto every bone.

.copy(source, recursive)

Extends Mesh.copy. Gives this mesh its own skeleton — source.skeleton:clone(), a deep copy of the pose (see Skeleton.clone()) — rather than sharing the source's by reference; otherwise every copy's AnimationMixer would write into the same node list and their poses would fight each other. bindMatrix and bindMatrixInverse are still carried over by reference, and geometry/material stay shared via Mesh.copy, as in three.js.

Differences from three.js

  • The mesh node's own transform is not cancelled out of the palette. Skinned vertices already sit in skeleton space, so jointWorld * inverseBind places them correctly; folding in inverse(meshWorld) — as three.js's bindMode == "attached" path does — would apply the node's scale a second time here. This is a deliberate, baked-in engine convention rather than a configurable bindMode.
  • No boneTexture/uniform-array split — the palette is a plain Lua array of Matrix4, handed to the shader by the renderer.
  • .copy() deep-clones .skeleton rather than sharing it by reference — closer to three.js's own SkinnedMesh.clone(), which (via Object3D.copy cloning children) ends up giving each clone independent Bone objects too.

SkinnedMesh

Mesh, деформируемый скелетом. Наследует Mesh (а через него Object3D) и получает их API. Математика палитры живёт в importer.common и используется совместно с путём сырого импортёра; этот класс только решает, какие узлы читать, и кэширует получившиеся матрицы для рендерера.

local mesh = SkinnedMesh:new(geometry, material)
mesh:bind(skeleton)

Constructor

SkinnedMesh(geometry, material)

Properties

СвойствоТипПо умолчаниюОписание
skeletonSkeletonnilУстанавливается .bind().
bindMatrixMatrix4nilУстанавливается .bind(), когда передана матрица.
bindMatrixInverseMatrix4nilОбратная к bindMatrix, вычисляется в .bind().

Также наследует .geometry, .material, .skin, .bindShapeMatrix от Mesh.

Methods

.isSkinnedMesh()

Возвращает true.

.bind(skeleton, bindMatrix)

Прикрепляет Skeleton. Если передан bindMatrix, также сохраняет его и обратную к нему.

.palette()

Возвращает массив матриц костей для текущего кадра, либо nil, если нет привязанного скелета со скином. Скелет владеет списком узлов, поэтому палитра следует за тем, что последним записал в него миксер анимации. Если задан bindShapeMatrix (Collada), он умножается на каждую кость.

.copy(source, recursive)

Расширяет Mesh.copy. Даёт этому мешу собственный скелет — source.skeleton:clone(), глубокую копию позы (см. Skeleton.clone()) — вместо совместного использования скелета источника по ссылке; иначе AnimationMixer каждой копии писал бы в один и тот же список узлов, и их позы конфликтовали бы друг с другом. bindMatrix и bindMatrixInverse по-прежнему переносятся по ссылке, а геометрия/материал остаются общими через Mesh.copy, как в three.js.

Differences from three.js

  • Собственный трансформ узла меша не вычитается из палитры. Скиннированные вершины уже находятся в пространстве скелета, поэтому jointWorld * inverseBind размещает их корректно; добавление inverse(meshWorld) — как это делает путь three.js с bindMode == "attached" — применило бы масштаб узла второй раз. Это осознанная, зашитая в движок конвенция, а не настраиваемый bindMode.
  • Нет разделения boneTexture/uniform-массив — палитра — это обычный Lua-массив Matrix4, передаваемый шейдеру рендерером.
  • .copy() глубоко клонирует .skeleton, а не делится им по ссылке — ближе к собственному SkinnedMesh.clone() в three.js, который (через клонирование детей в Object3D.copy) в итоге тоже даёт каждому клону независимые объекты Bone.
