TreeLua / Animation

AnimationClip

One named animation — a thin, typed face over an importer's clip record. Played back through an AnimationAction on an AnimationMixer. A clip keeps a reference to the module that can sample it, because glTF and Collada animate different things — glTF writes TRS channels per node, Collada bakes whole matrices — and each importer ships the sampler that understands its own tracks, so the mixer never branches on format.

Constructor

AnimationClip(name, duration, tracks)

name defaults to "", duration to 0, tracks to {}. Ordinary code reaches clips through a loader's animations array (built via .fromImporter), not this constructor directly.

Properties

PropertyTypeDefaultDescription
typestring"AnimationClip"
namestring""Clip identifier, used to look it up by name.
durationnumber0Clip length in seconds.
trackstable[]{}Per-node TRS tracks: { node, path, times, values, interp }, where path is "translation", "rotation" or "scale".
fps / framesnumber—Set by .fromImporter when the source clip carries them.

Methods

:isAnimationClip()

Returns true. Type-check facade.

:fromImporter(clip, sampler, nodes)

Wraps an importer clip record. sampler is importer.gltf.animation or importer.dae.animation — whichever module produced clip — and nodes is the flat node list its sample/evaluate read and write. This is how loaders build the clips they hand back.

:sample(time, loop)

Writes this clip's pose at time directly into .nodes via the stored sampler. loop false clamps at the clip's ends instead of wrapping. This is the pre-blending path: the mixer only calls it when mixer.blending == false, since it writes straight into the shared node list rather than returning a value an accumulator could combine with another clip's.

:accumulate(accumulator, time, loop, weight)

Evaluates every track at time and hands the values to accumulator (a PoseAccumulator) scaled by weight, instead of writing them into the nodes. This is what makes blending multiple simultaneous clips possible: it relies on the sampler exposing evaluate(track, time), which returns values rather than mutating anything, so several clips' contributions can be combined before anything is written. No-op if the sampler has no evaluate.

:resetDuration()

Recomputes .duration from the latest keyframe timestamp across all tracks.

:findByName(clips, name)

Scans clips for one whose .name matches, or returns nil. three.js's static AnimationClip.findByName, called as a method per this engine's convention.

:clone()

Returns a new AnimationClip with the same name, duration, tracks, sampler and node reference. Tracks and sampler are shared (read-only), not deep-copied.

:withNodes(nodes)

Clones this clip and retargets it to write into a different instance's node list. What a Model's clips need after model:createInstance() gives that instance its own cloned Skeleton nodes — the track data and sampler stay shared, only the destination changes.

Differences from three.js

  • Tracks are plain Lua tables ({ node, path, times, values, interp }) rather than KeyframeTrack subclass instances (VectorKeyframeTrack, QuaternionKeyframeTrack, etc.).
  • No serialization helpers (toJSON, parse, CreateFromMorphTargetSequence, parseAnimation, ...) — clips are constructed directly from loader data via .fromImporter.
  • :sample(), :accumulate() and :withNodes() have no three.js equivalent — they exist because this engine keeps clip playback format-agnostic through a per-importer sampler module, and because a clip needs to be retargetable across a Model's independent instances.

TreeLua / Animation

AnimationClip

Одна именованная анимация — тонкая типизированная обёртка над записью клипа импортёра. Воспроизводится через AnimationAction на AnimationMixer. Клип хранит ссылку на модуль, который умеет его сэмплировать, потому что glTF и Collada анимируют разные вещи — glTF пишет TRS-каналы по узлам, Collada запекает целые матрицы — и каждый импортёр поставляет свой сэмплер, понимающий собственные дорожки, так что миксер никогда не разветвляется по формату.

Constructor

AnimationClip(name, duration, tracks)

name по умолчанию "", duration — 0, tracks — {}. Обычный код получает клипы через массив animations загрузчика (собранный через .fromImporter), а не напрямую через этот конструктор.

Properties

СвойствоТипПо умолчаниюОписание
typestring"AnimationClip"
namestring""Идентификатор клипа, используется для поиска по имени.
durationnumber0Длительность клипа в секундах.
trackstable[]{}Дорожки TRS по узлам: { node, path, times, values, interp }, где path — "translation", "rotation" или "scale".
fps / framesnumber—Устанавливаются .fromImporter, если исходный клип их несёт.

Methods

:isAnimationClip()

Возвращает true. Фасад проверки типа.

:fromImporter(clip, sampler, nodes)

Оборачивает запись клипа импортёра. sampler — это importer.gltf.animation или importer.dae.animation — какой модуль произвёл clip — а nodes — плоский список узлов, который читают и пишут его sample/evaluate. Именно так загрузчики собирают клипы, которые возвращают наружу.

:sample(time, loop)

Записывает позу этого клипа в момент time напрямую в .nodes через сохранённый сэмплер. loop равный false зажимает по краям клипа вместо зацикливания. Это путь до появления блендинга: миксер вызывает его только когда mixer.blending == false, поскольку он пишет прямо в общий список узлов, а не возвращает значение, которое аккумулятор мог бы объединить со значением другого клипа.

:accumulate(accumulator, time, loop, weight)

Вычисляет каждую дорожку в момент time и передаёт значения в accumulator (PoseAccumulator), масштабируя на weight, вместо записи их в узлы. Именно это делает возможным блендинг нескольких одновременных клипов: метод полагается на то, что сэмплер предоставляет evaluate(track, time), которая возвращает значения, а не что-то мутирует, так что вклад нескольких клипов можно объединить до того, как что-либо будет записано. Ничего не делает, если у сэмплера нет evaluate.

:resetDuration()

Пересчитывает .duration по последней метке времени ключевого кадра среди всех дорожек.

:findByName(clips, name)

Ищет в clips клип с совпадающим .name, либо возвращает nil. Статический метод three.js AnimationClip.findByName, вызываемый как обычный метод по конвенции этого движка.

:clone()

Возвращает новый AnimationClip с теми же name, duration, tracks, сэмплером и ссылкой на узлы. Дорожки и сэмплер общие (только для чтения), не копируются глубоко.

:withNodes(nodes)

Клонирует этот клип и ретаргетит его на запись в список узлов другого инстанса. То, что нужно клипам Model после того, как model:createInstance() даёт этому инстансу собственные клонированные узлы Skeleton — данные дорожек и сэмплер остаются общими, меняется только пункт назначения записи.

Differences from three.js

  • Дорожки — обычные Lua-таблицы ({ node, path, times, values, interp }), а не экземпляры подклассов KeyframeTrack (VectorKeyframeTrack, QuaternionKeyframeTrack и т.д.).
  • Нет средств сериализации (toJSON, parse, CreateFromMorphTargetSequence, parseAnimation, ...) — клипы создаются напрямую из данных загрузчика через .fromImporter.
  • :sample(), :accumulate() и :withNodes() не имеют аналога в three.js — они существуют потому, что этот движок держит воспроизведение клипа независимым от формата через модуль-сэмплер на каждый импортёр, и потому что клип должен быть ретаргетируемым между независимыми инстансами Model.
